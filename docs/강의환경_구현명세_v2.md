# 강의환경 구현 명세 v2

> **대상 Codex에게:** 이 문서만으로 구현 또는 기동하라. 이미지, 서비스 수, 스킬 목록을 임의로 바꾸지 말라. 명시된 선행 파일이 없으면 파일명을 보고하고 중단한다.

**Goal:** macOS OrbStack와 Windows Docker Desktop에서 Oracle AI Database 26ai Free Lite, FastAPI, React/Vite, Codex CLI를 정확히 두 컨테이너로 실행하고, GET /api/health가 Oracle 연결 성공을 반환하게 한다.

**Architecture:** db는 외부 포트가 없는 Oracle DB다. app은 Oracle Linux 8에서 FastAPI(8000)와 Vite(5173)를 함께 실행하며 Compose DNS db:1521/FREEPDB1로 DB에 접근한다. Codex 인증은 런타임 /tmp/codex-home에만 둔다.

**Tech Stack:** Docker Compose v2, Oracle Linux 8, Oracle AI Database 26ai Free Lite, Python 3.9/FastAPI/oracledb, Node.js 20/React 19/Vite 6, Codex CLI.

## 1. 고정 제약과 사전 점검

- 서비스는 db, app 정확히 두 개다. Redis, nginx, 별도 frontend, object storage는 추가하지 않는다.
- app 베이스는 container-registry.oracle.com/os/oraclelinux:8이고, db 베이스는 container-registry.oracle.com/database/free:latest-lite다.
- 두 컨테이너는 root에서 dnf와 yum 명령이 성공해야 한다.
- DB에는 호스트 포트를 열지 않는다. app만 8000:8000, 5173:5173을 연다.
- 메모리 제한은 db 2500m, app 1250m이다.
- Docker/OrbStack 저장소에 최소 20GB 여유 공간이 필요하다. 기존 이미지·컨테이너 삭제는 명시적인 소유자 승인 없이는 하지 않는다.
- Apple Silicon은 linux/arm64, Windows x64는 linux/amd64다.
- npm 설치에는 https://registry.npmmirror.com을 명시하고 사용자 전역 npm 설정을 변경하지 않는다.
- Oracle 비밀번호에는 대문자·소문자·숫자가 필요하며 따옴표를 사용하지 않는다.

먼저 실행한다.

~~~
pwd
test -f compose.yaml && test -f .env.example && echo existing-project || echo bootstrap-required
docker compose version
docker context show
df -h .
docker system df
~~~

existing-project면 2절을 실행한다. bootstrap-required면 3절부터 모두 생성한다. Compose v2가 없거나 여유 공간이 20GB 미만이면 배포하지 말고 보고한다.

## 2. 기존 프로젝트 실행

위 파일 구조와 생성된 infra/codex-profile/skills가 있을 때만 실행한다.

~~~
cp -n .env.example .env

docker compose --env-file env/macos-arm64.env up --build -d
./scripts/verify-compose.sh env/macos-arm64.env
~~~

Windows x64에서는 env/windows-amd64.env를 쓴다. OrbStack에서 BuildKit session header 오류가 실제 발생할 때만 다음 단발 우회를 쓴다.

~~~
DOCKER_BUILDKIT=0 docker compose --env-file env/macos-arm64.env up --build -d
~~~

ARM 매니페스트 오류가 실제 확인된 경우에만 다음 macOS 폴백을 쓴다.

~~~
docker compose --env-file env/macos-amd64-fallback.env up --build -d
~~~

.env의 예제 비밀번호는 개발용이다. 기존 oracle-data volume이 있으면 .env의 ORACLE_PWD를 변경해도 SYSTEM 비밀번호는 자동 변경되지 않는다. 새 DB가 꼭 필요할 때만 승인 후 docker compose down -v를 사용한다.

## 5. FastAPI와 테스트

backend/__init__.py는 빈 파일이다.

~~~python
# backend/settings.py
from dataclasses import dataclass
import os
@dataclass(frozen=True)
class Settings:
    oracle_user: str = os.getenv("ORACLE_APP_USER", "lecture_app")
    oracle_password: str = os.getenv("ORACLE_APP_PASSWORD", "")
    oracle_dsn: str = os.getenv("ORACLE_DSN", "db:1521/FREEPDB1")
settings = Settings()

# backend/database.py
from backend.settings import settings
def database_is_available() -> bool:
    try:
        import oracledb
        with oracledb.connect(user=settings.oracle_user, password=settings.oracle_password, dsn=settings.oracle_dsn) as connection:
            with connection.cursor() as cursor:
                cursor.execute("SELECT 1 FROM dual")
                return cursor.fetchone() == (1,)
    except Exception:
        return False

# backend/main.py
from fastapi import FastAPI, status
from fastapi.responses import JSONResponse
from backend.database import database_is_available
app = FastAPI(title="Lecture Environment API")
@app.get("/api/health")
def health() -> JSONResponse:
    if database_is_available():
        return JSONResponse({"status": "ok", "database": "connected"})
    return JSONResponse({"status": "degraded", "database": "unavailable"}, status_code=status.HTTP_503_SERVICE_UNAVAILABLE)
~~~

~~~sh
#!/bin/sh
set -eu
project_root=$(CDPATH= cd -- "$(dirname -- "$0")/.." && pwd)
manifest="$project_root/infra/codex-profile/skill-manifest.txt"
destination="$project_root/infra/codex-profile/skills"
rm -rf "$destination"; mkdir -p "$destination"
while IFS= read -r skill; do
  [ -n "$skill" ] || continue
  source="$project_root/.codex/skills/$skill"
  [ -f "$source/SKILL.md" ] || { echo "Missing skill source: $skill" >&2; exit 1; }
  cp -RL "$source" "$destination/$skill"
  test -f "$destination/$skill/SKILL.md"
done < "$manifest"
expected=$(grep -cve '^[[:space:]]*$' "$manifest")
actual=$(find "$destination" -mindepth 1 -maxdepth 1 -type d | wc -l | tr -d ' ')
test "$expected" = "$actual"
echo "Copied $actual Codex skills"
~~~

## 8. 기동 검증과 완료 조건

~~~sh

첫 번째 명령은 수강생용 기본 검증이며, 두 번째 명령은 교육자 로컬에서 생성한 27개 선택 스킬을 엄격 검증한다.

~~~
chmod 755 scripts/verify-compose.sh

docker compose --env-file env/macos-arm64.env up --build -d
./scripts/verify-compose.sh env/macos-arm64.env
~~~

다음이 모두 참일 때만 완료를 선언한다.

1. docker compose ps에 db, app만 있으며 db는 healthy다.
2. curl http://localhost:8000/api/health가 정확히 {"status":"ok","database":"connected"}를 반환한다.
3. curl http://localhost:5173가 성공한다.
4. app과 db root에서 dnf --version, yum --version이 성공한다.
5. app에서 codex --version이 성공하고 /tmp/codex-home/skills의 최상위 디렉터리가 정확히 27개다.
6. backend 테스트 2개와 frontend 테스트 1개가 통과한다.

사람이 인증을 수행한다.

~~~
docker compose exec -it app codex login
docker compose exec -it app codex
~~~

인증은 /tmp/codex-home에만 있으므로 컨테이너 재생성 시 사라지는 것이 의도된 동작이다.

## 9. 실패 진단 순서

- API가 503이면 docker compose logs --tail=120 db app을 먼저 읽는다. ORA-01017이면 startup 마운트, 앱 사용자 비밀번호, 사용자 생성 로그를 점검한다.
- 사용자 생성 로그가 없으면 scripts/setup이 아니라 scripts/startup으로 마운트됐는지 확인한다.
- no space left on device면 docker system df 결과를 제시하고 이미지 삭제 승인을 받는다.
- BuildKit gRPC 헤더 오류면 2절의 DOCKER_BUILDKIT=0 우회를 한 번만 쓴다.
- ARM 매니페스트 오류가 확인되면 macOS AMD64 폴백 환경 파일을 쓴다.
- 스킬 수가 27개가 아니면 app 재빌드 전에 manifest와 infra/codex-profile/skills를 바로잡는다.
