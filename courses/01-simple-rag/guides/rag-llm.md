# RAG·LLM 공통 가이드

## 모드와 설정

생성할 `.env.example`의 기본값은 다음과 같다. `.env`는 데모 디렉터리에서만 읽는다.

```dotenv
RAG_MODE=offline
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
RAG_TOP_K=4
```

기본은 외부 호출이 없는 `offline`이다. `openai`로 설정하고 키가 있으면 임베딩·생성을 사용한다. 온라인을 요청했으나 키가 없으면 키워드 검색으로 동작하고 `reason=missing_api_key`를 표시한다. Codex ChatGPT 로그인과 이 앱의 API 인증은 별개다.

기본 생성 모델은 교육용 경량 선택이며 최신 또는 모든 계정의 사용 가능성을 보장하지 않는다. 구현할 때 Python 3.9와 설치 SDK의 호환성을 확인한다. 생성은 Responses API, 임베딩은 Embeddings API를 사용하고 불필요한 모델별 옵션을 추가하지 않는다.

참고: [생성 모델](https://developers.openai.com/api/docs/models/gpt-5-mini), [임베딩 모델](https://developers.openai.com/api/docs/models/text-embedding-3-small), [Responses API](https://developers.openai.com/api/docs/guides/text).

## 지식 처리

- UTF-8 MD를 제목/조항 단위로 나눈다. 긴 조항만 최대 800자와 100자 중첩으로 나누고 파일명·조항·안정적인 chunk ID를 보존한다.
- 첫 실행과 `reindex.sh`에서 색인한다. 원문 해시, 청크 설정, 검색 방식, 임베딩 모델·차원을 색인 메타데이터에 기록한다. 내용·설정이 달라지면 재생성한다.
- 색인은 `data/index.json`에 원자적으로 교체한다. 앱 기동과 재색인은 동일한 잠금을 사용해 동시 쓰기를 막는다. Git에는 넣지 않는다.
- 오프라인은 정규화한 한글/영문 토큰 및 한글 부분 문자열로 점수를 계산하는 설명 가능한 키워드 검색을 구현한다. 점수 0은 제외하고 상위 4개를 반환한다. 테스트 질문을 하드코딩하지 않는다.
- 온라인은 문서 임베딩을 재사용하고 질문을 임베딩해 코사인 유사도로 상위 4개를 검색한다. 문서가 바뀌지 않았으면 매 질문마다 전체 임베딩을 재요청하지 않는다.
- 점수는 검색 순위용이며 답변의 신뢰 확률이 아니다. 검색 결과가 있다는 사실만으로 질문의 답이 있다고 판단하지 않는다.

## 생성과 오류

LLM에 전달하는 컨텍스트에는 검색된 chunk ID, 파일명, 조항, 본문을 포함한다. 근거로 제공된 문서만 사용하고, 질문에 필요한 규정이 없으면 없다고 답하도록 지시한다. 인용 ID는 검색 결과 안의 것만 허용하며 서버에서 유효성을 확인한다.

오프라인에서는 `answer=null`과 검색 근거를 반환한다. 화면은 “검색 전용: 생성 답변 없음”으로 표시한다. 검색 결과가 없으면 “관련 근거를 찾지 못했습니다”를 표시한다. 해외 지사 주차비처럼 유사한 문서는 검색되더라도 필요한 조항이 없는 경우를 구분해 학습한다.

온라인 요청은 유한한 타임아웃(기본 30초), 최대 1회 재시도를 적용한다. 인증/요금/네트워크 오류를 정상 생성으로 위장하지 않는다. 검색이 가능하면 근거와 `mode=offline`, `reason=provider_error`, `answer=null`로 반환한다. 원본 오류에서 키나 요청 헤더를 노출하지 않는다.

임베딩 요청 시 규정 본문, 질의 시 질문, 생성 시 검색 근거가 OpenAI에 전송될 수 있음을 화면과 README에 설명한다. 제공된 가상 자료만 기본으로 사용한다. 외부 오브젝트 스토리지·호스팅 벡터 저장소는 필요 없다.
